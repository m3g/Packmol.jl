These are the public functions of Packmol.jl. The functions of the recipes are documented on the Recipes page.

Packing engine

Packmol.packmol — Function
packmol(input_file::String; kargs...)

Read a Packmol input file, run the packing optimization, and write the output. Returns the built PackmolSystem (see packmol(::PackmolSystem) for details).

Paths in the input file (structure files, output, restart_from, restart_to) are relative to the directory of the input file.

With no input file, a file explorer is opened to choose it (see Packmol.pick_file). To disable the file explorer, set the environment variable PACKMOL_GUI="false".

source
packmol(; kargs...)

Choose a Packmol input file in a file browser, and run it.

The same as packmol(input_file; kargs...), with the file chosen in the file browser of Packmol.pick_file (disabled by setting the environment variable PACKMOL_GUI="false", in which case the file is asked for in the terminal).

source
packmol(packmol_system::PackmolSystem; kargs...)

Run the packing optimization on a PackmolSystem, mutating it in place (final molecule_positions, ...) and returning that same object — not a bare Bool — so callers can keep using it afterwards (e.g. to postprocess or re-write_output the packed coordinates, or to convert their representation, as with triclinic_to_dodecahedral).

The packing outcome is recorded in packmol_system.status: :packing_ready if it converged within nloop loops (both tolerance_precision and constraint_precision satisfied), :failed_packing if it did not, or :failed_initial_approximation if the initial approximation could not satisfy the constraints (written to the output file; the packing continues only if packmol_system.continue_failed_initial_packing is set), or :not_packed if packmol_system.check was set (initial approximation written, no packing attempted).

nloop (maximum number of packing loops, default 200), maxit (optimizer iterations per loop, default 800) and movefrac (maximum fraction of the molecules of each type moved per loop, default 0.05) take precedence over the values set in the input file (packmol_system.nloop, packmol_system.max_iter and packmol_system.movefrac).

nthreads (maximum number of threads used, default: all the threads of the Julia session) takes precedence over packmol_system.nthreads (the input keyword nthreads).

Packmol.structure_type — Function
structure_type(filename; number, constraints=Constraint[], tolerance=2.0, radius=nothing,
                fixed=nothing, center=:none, residue_numbering=-1, D=3, T=Float64)

Build a StructureType for number copies of the molecule read from the PDB file filename, without going through an input file. Every constraint in constraints applies to the whole molecule.

atom_constraints gives constraints that apply only to some atoms of the molecule (as the atoms ... end atoms blocks of an input file): a vector of indices => constraints pairs, with the indices of the atoms in the structure file and one constraint or a vector of them. For example, atom_constraints = [[31, 32] => BelowPlane([0,0,1], 2.0)].

radius sets a uniform atom radius; if not given, it defaults to tolerance/2 (so that two touching atoms' radii sum to tolerance, matching the input file default).

fixed, if given, is a (cm, angles) pair of 3-vectors that fixes the molecule at that position/orientation instead of packing it; center (:none, :geometric, or :mass) then controls how the molecule is centered before that transformation is applied — equivalent to the input file's fixed/center/centerofmass keywords.

Example

julia> using Packmoljulia> st = structure_type("water.pdb"; number=1000, constraints=[InsideBox([0,0,0],[40,40,40])])

PDBToolsBase.get_atoms — Function
get_atoms(packmol_system::PackmolSystem)

Returns the atoms of the packed system, with their current coordinates.

The result is a Vector{PDBToolsBase.Atom}, generated from packmol_system.molecule_positions on each call (never cached on packmol_system itself), the same way write_output computes what it writes to file. Residue numbering follows each structure type's residue_numbering (resnumbers) setting, and chain identifiers follow chain/changechains.

When periodic boundary conditions are set (packmol_system.unitcell), each molecule's center of mass is wrapped into the unit cell as a rigid unit (a molecule straddling a periodic boundary is never torn in two across it), in the representation selected by packmol_system.periodic_boundary_style: the ordinary skewed-parallelepiped shape (:triclinic, the default), or, after triclinic_to_dodecahedral/triclinic_to_octahedral (packmol_system) has been called, the corresponding Wigner-Seitz "compact" shape (:dodecahedral/:octahedral) — see those functions and their dodecahedral_to_triclinic/octahedral_to_triclinic counterparts.

source
Packmol.write_output — Function
write_output(packmol_system::PackmolSystem)

Write packed coordinates to the output file specified in packmol_system.output_file. Residue numbering follows each structure type's residue_numbering (resnumbers) setting, chain identifiers follow chain/changechains, and a CRYST1 record is added when add_box_sides is set or the system has periodic boundary conditions. Also writes any configured restart_to file(s) from the current molecule positions, unless write_restart=false. Returns the path of the file that was written. See get_atoms for how the written coordinates are computed (including PBC wrapping and packmol_system.periodic_boundary_style).

Dodecahedral periodic box

Packmol.dodecahedral_unitcell — Function
dodecahedral_unitcell(::Type{T}, d) where {T}

3x3 unit cell matrix (columns are the cell vectors) for a rhombic dodecahedron of "size" d, using the standard MD convention (matching GROMACS's editconf -bt dodecahedron -d d):

v1 = (d, 0, 0)v2 = (0, d, 0)v3 = (d/2, d/2, d/√2)

equivalently a = b = c = d, α = β = 60°, γ = 90° in CRYST1 terms. d is the guaranteed minimum-image distance in every direction — the point of the shape is that, for a given cell volume, it gets a bigger minimum-image distance than a cube does, by trading away the cube's wasted corner volume relative to a sphere (about 70.7% of a cube's volume for the same d).

Use as PackmolSystem(structure_types; unitcell=dodecahedral_unitcell(Float64, d), unitcell_center=[cx,cy,cz], ...) — equivalent to the input file's pbc dodecahedral cx cy cz d.

source
Packmol.triclinic_to_dodecahedral — Function
triclinic_to_dodecahedral(x, unitcell, center)

Remaps the position(s) x to the rhombic-dodecahedron shape of the periodic cell.

x is mapped to its periodic image closest to center: the rhombic-dodecahedron (Wigner-Seitz) fundamental domain of the cell, as opposed to the skewed-parallelepiped one of wrap_to_center. x can be a single SVector{3} or a vector of them.

See also dodecahedral_to_triclinic for the reverse mapping.

source
triclinic_to_dodecahedral(x, packmol_system::PackmolSystem)

Remaps the position(s) x to the rhombic-dodecahedron shape of the periodic cell of packmol_system.

The same as triclinic_to_dodecahedral(x, packmol_system.unitcell, packmol_system.unitcell_center).

source
triclinic_to_dodecahedral(packmol_system::PackmolSystem)

Selects the rhombic-dodecahedron shape for the output of packmol_system, and returns it.

It sets packmol_system.periodic_boundary_style = :dodecahedral; unlike the coordinate-remapping methods above, it touches no coordinates itself. It just selects, for subsequent calls to get_atoms/write_output, which fundamental-domain shape molecule positions get wrapped into: the rhombic-dodecahedron (Wigner-Seitz) "compact" shape instead of the default triclinic one. The actual remapping happens on demand each time get_atoms runs, not here.

Requires packmol_system.unitcell to already be set (typically to a dodecahedral cell — e.g. via dodecahedral_unitcell or the input file's pbc dodecahedral ... — though any triclinic cell works).

source
Packmol.dodecahedral_to_triclinic — Function
dodecahedral_to_triclinic(x, unitcell, center)

Remaps the position(s) x to the parallelepiped shape of the periodic cell.

The other direction of triclinic_to_dodecahedral: x is mapped into the skewed-parallelepiped fundamental domain of the cell (the ordinary unitcell representation, as in the CRYST1 record of PDB files), with wrap_to_center. x can be a single SVector{3} or a vector of them.

source
dodecahedral_to_triclinic(x, packmol_system::PackmolSystem)

Remaps the position(s) x to the parallelepiped shape of the periodic cell of packmol_system.

The same as dodecahedral_to_triclinic(x, packmol_system.unitcell, packmol_system.unitcell_center).

dodecahedral_to_triclinic(packmol_system::PackmolSystem)

Selects the parallelepiped shape (the default) for the output of packmol_system, and returns it.

The other direction of triclinic_to_dodecahedral(packmol_system): it sets packmol_system.periodic_boundary_style = :triclinic, so get_atoms/write_output go back to wrapping molecule positions into the ordinary skewed-parallelepiped shape.

Octahedral periodic box

Packmol.octahedral_unitcell — Function
octahedral_unitcell(::Type{T}, d) where {T}

3x3 unit cell matrix (columns are the cell vectors) for a truncated octahedron of "size" d, using the standard MD convention (matching GROMACS's editconf -bt octahedron -d d):

v1 = (d, 0, 0)v2 = (d/3, 2√2 d/3, 0)v3 = (-d/3, √2 d/3, √6 d/3)

equivalently a = b = c = d, α = γ = acosd(1/3) ≈ 70.53°, β = acosd(-1/3) ≈ 109.47° in CRYST1 terms — the Wigner-Seitz cell of a BCC lattice, built from a Minkowski-reduced (shortest-vectors) basis for it. d is the guaranteed minimum-image distance in every direction. For a given cell volume this gets a bigger minimum-image distance than a cube does (about 77.0% of a cube's volume for the same d) — a bit more volume than the rhombic dodecahedron needs for the same d (see dodecahedral_unitcell, ≈70.7%), but its shape is still often preferred for solvating a single roughly-spherical solute.

Use as PackmolSystem(structure_types; unitcell=octahedral_unitcell(Float64, d), unitcell_center=[cx,cy,cz], ...) — equivalent to the input file's pbc octahedral cx cy cz d.

Legacy (Fortran) Packmol and the file browser

Packmol.run_packmol_legacy — Function
run_packmol_legacy()
run_packmol_legacy(input_file::String)

Runs the packmol executable with the input file input_file. This will run the classical http://m3g.iqm.unicamp.br/packmol program, which is a pre-compiled binary. The input file is a text file with the same syntax as the packmol input files.

The binary is provided by the Packmol_jll package, which must be installed and loaded (using Packmol_jll) for run_packmol_legacy to be available.

If no input file is provided, a file explorer will be opened to choose the input file (see Packmol.pick_file).

To disable the file explorer, set the environment variable PACKMOL_GUI="false".

source
Packmol.pick_file — Function
pick_file()

Opens a file dialog to choose the Packmol input file, and returns its path.

The dialog is provided by tools that come with the operating system — osascript on macOS, PowerShell on Windows, and zenity or kdialog on Linux — so no GUI toolkit is bundled with Packmol. If none of them is available, the path is read from the terminal instead.

To disable the file dialog, set the environment variable PACKMOL_GUI="false".
